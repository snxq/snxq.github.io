# snxq.cc 个人网站内容与交互设计

- 日期：2026-07-20
- 状态：已确认的初版设计，可根据原型效果继续微调
- 域名：`snxq.cc`

## 1. 目标

`snxq.cc` 是以长期网名“snxq / 晓琦”为核心的个人网站，用于承载项目、文章、个人信息、短笔记、近况、收藏、使用清单、生活内容，以及开源与技术经历。

网站不以传统导航和栏目首页作为主要入口，而是用一个单向命令输入区域吸引访客探索。访客输入命令后，网站在当前页面内打开样式窗口展示内容，不触发浏览器原生弹窗，也不跳转到新页面。

核心体验目标是：

1. 访客第一次进入时感到网站具有个性，并愿意尝试和探索。
2. 正式内容易于发现，不能为了神秘感牺牲基本可用性。
3. 命令逻辑全部由后端负责，前端专注交互状态和内容样式。
4. 内容模型和视觉细节允许在看到原型效果后逐步调整。

## 2. 内容范围

网站需要支持以下内容类别，但不在本设计中规定具体条目、筛选标准或更新频率；这些由后续运营决定。

- 关于我
- 项目
- 长文章
- 短笔记与随想
- Now：当前近况
- 收藏与书签
- Uses：设备、软件、工具及工作环境
- 生活内容：照片、旅行、音乐、书影音等
- 开源贡献与技术经历
- 帮助信息
- 彩蛋与扩展内容

## 3. 核心交互

### 3.1 命令入口

页面提供单向命令输入区域。访客可以输入固定命令，也可以输入后端支持的中文、英文或少量自然语言别名。

前端只提交访客的原始输入，不维护命令表，不解析命令，也不进行别名匹配。

### 3.2 页面内窗口

有效命令会打开一个网页内部的样式窗口：

- 不使用浏览器原生弹窗。
- 不离开当前页面。
- 同一时间只展示一个内容窗口。
- 新命令成功后，当前窗口切换为新的内容。
- 关闭窗口后回到命令输入区域。
- 第一版不支持窗口拖动、缩放或多窗口堆叠。

### 3.3 列表与详情

需要列表与详情的内容采用单窗口内导航：

1. 命令打开栏目列表或概览。
2. 点击条目后，在同一个窗口中切换到详情。
3. 标题栏显示返回按钮。
4. 返回时恢复原有列表状态和滚动位置。
5. 进入详情时，详情内容从顶部开始展示。

### 3.4 命令历史

命令区域保留当前访问会话的探索记录：

```text
> projects
已打开「项目」

> 最近在干什么
已打开「Now」
```

规则：

- 显示访客的原始输入。
- 系统反馈使用后端响应中的文案。
- 正式内容只在内容窗口中展示，历史区域不输出大段正文。
- 成功记录可以支持再次打开相应内容。
- 无效命令也保留在历史中。
- 默认在刷新页面后清空；是否持久化可在原型阶段决定。

## 4. 命令系统职责

### 4.1 后端负责

- 接收和解析原始输入。
- 判断命令是否有效。
- 识别固定命令、中文或英文别名，以及自然语言别名。
- 将输入映射到规范命令。
- 定义公开命令与隐藏彩蛋命令。
- 返回帮助内容。
- 返回规范化后的独立命令总数。
- 返回系统反馈文案。
- 返回窗口标题、内容类型和内容数据。
- 返回列表及详情数据。

### 4.2 前端负责

- 提交原始输入。
- 展示输入历史和后端反馈。
- 管理请求、窗口、列表与详情状态。
- 根据强类型响应选择内容模板。
- 渲染加载、空内容、无效命令和异常状态。
- 负责响应式布局和视觉表现。

前端不得根据标题文字推断内容类型，也不得内置命令名称、别名、命令数量或彩蛋清单。

### 4.3 命令数量口径

命令总数由后端按规范化后的独立命令统计。

例如：

```text
projects
项目
看看你的项目
```

如果三种输入都映射至同一个规范命令，则只计作一种命令。隐藏彩蛋命令计入总数，但不在帮助内容中公开名称。

无效命令的目标反馈为：

```text
当前命令无效，总计支持 xx 种命令。
```

其中完整文案和 `xx` 都由后端返回，前端不自行拼接或统计。

## 5. 通信与数据协议

### 5.1 gRPC-Web

浏览器前端通过 gRPC-Web 与后端通信，而不是直接调用原生 HTTP/2 gRPC。

典型链路为：

```text
浏览器前端
  -> gRPC-Web
  -> gRPC-Web 兼容入口或代理
  -> 原生 gRPC 后端服务
```

前后端共享 `.proto` 协议，并生成对应的客户端与消息类型。前端通过生成代码将 Protobuf 响应反序列化为强类型对象，不手工解析二进制数据。

第一版使用 unary RPC：一次输入对应一次请求和响应。不需要客户端流、服务端流或双向流。

### 5.2 强类型内容

后端返回结构化 Protobuf 消息，不返回 Markdown、任意 HTML 或通用 JSON 字符串。

不同内容模板使用 `oneof` 表达，避免使用窗口标题或松散字符串决定前端组件。示意协议如下：

```proto
message CommandResponse {
  string request_id = 1;
  string message = 2;
  optional WindowContent window = 3;
}

message WindowContent {
  string id = 1;
  string title = 2;
  string subtitle = 3;
  optional string updated_at = 4;

  oneof body {
    AboutContent about = 10;
    ProjectsContent projects = 11;
    PostsContent posts = 12;
    NotesContent notes = 13;
    NowContent now = 14;
    BookmarksContent bookmarks = 15;
    UsesContent uses = 16;
    LifeContent life = 17;
    OpenSourceContent open_source = 18;
    HelpContent help = 19;
    RichContent custom = 20;
  }
}
```

最终字段编号、可选性、分页方式和错误模型在实现计划阶段细化。

## 6. 统一窗口结构

所有内容类型共享相同的窗口外壳。

### 6.1 标题栏

- 返回按钮：仅在详情状态显示。
- 窗口标题。
- 可选副标题或状态。
- 关闭按钮。

### 6.2 内容区

- 根据 Protobuf `oneof` 分支选择模板。
- 支持列表、概览或详情内容。
- 内容区独立滚动，避免影响整个页面的命令输入区域。

### 6.3 底部信息

按后端数据选择性展示：

- 最近更新时间。
- 内容数量。
- 相关提示。
- 允许的结构化操作。

统一外壳不意味着所有内容长得相同。各栏目使用专属模板，只共享窗口行为和基础视觉语言。

## 7. 内容模板

### 7.1 关于我

直接展示结构化个人档案，不要求列表与详情切换。可支持：

- 显示名称
- 一句话介绍
- 详细简介
- 头像或代表图
- 所在地区
- 关注领域标签
- 社交链接
- 联系方式
- 当前状态

### 7.2 项目

默认使用项目卡片列表。列表项可支持：

- 项目 ID
- 名称
- 一句话摘要
- 封面或图标
- 标签
- 状态
- 时间信息
- 精选标记
- 链接集合

点击后在同一窗口进入详情，详情可增加完整介绍、结构化正文、图片集合、技术信息及相关链接。

### 7.3 长文章

列表项可支持：

- 文章 ID
- 标题
- 摘要
- 封面
- 发布时间
- 更新时间
- 标签
- 预计阅读时间

点击后在同一窗口展示结构化全文，并允许返回文章列表。

### 7.4 短笔记与随想

采用按时间排列的信息流。单条笔记可支持：

- 笔记 ID
- 发布时间
- 简短正文
- 标签
- 相关链接
- 图片

默认直接连续展示；较长内容可按效果决定是否展开。

### 7.5 Now

作为当前状态快照，而不是历史文章列表。可支持：

- 页面更新时间
- 当前状态概述
- 正在做
- 正在学习
- 正在阅读或观看
- 最近关注
- 补充内容块

### 7.6 收藏与书签

使用分组链接清单。可支持：

- 分组名称和说明
- 链接标题与地址
- 简短推荐语
- 图标或封面
- 标签

外部网页元数据由后端或运营提供，前端不自行抓取。

### 7.7 Uses

按类别组织设备、软件、工具、环境和服务。条目可支持：

- 类别名称
- 项目名称
- 型号或版本
- 使用说明
- 官方链接
- 图片或图标

### 7.8 生活内容

使用图文集合。条目可支持：

- 内容 ID
- 标题
- 摘要
- 日期
- 地点
- 封面
- 图片集合
- 标签
- 结构化正文

点击后在同一窗口展示完整图文详情。

### 7.9 开源贡献与技术经历

允许组合两类数据：

- 贡献条目：项目、贡献说明、时间、角色、链接。
- 经历节点：标题、时间范围、说明、标签、相关成果。

前端只渲染后端数据，不自行读取 GitHub 或计算贡献指标。

### 7.10 帮助

帮助内容完全由后端提供：

- 简短介绍
- 公开命令列表
- 命令名称
- 命令说明
- 输入示例
- 补充提示

彩蛋命令不包含在公开帮助中。

### 7.11 彩蛋与扩展内容

提供通用的 `RichContent` 模板，用于多数彩蛋和非固定栏目，减少每增加一个彩蛋就修改前端的成本。

通用模板可以组合标题、段落、图片、引用、代码块、链接、分隔线、列表、提示和结构化按钮。只有确实需要独立视觉或交互的彩蛋，才新增 Protobuf 消息类型和前端模板。

## 8. 结构化正文块

文章、项目详情、生活图文和彩蛋内容可以共用结构化正文块：

```proto
message ContentBlock {
  oneof block {
    HeadingBlock heading = 1;
    ParagraphBlock paragraph = 2;
    ImageBlock image = 3;
    GalleryBlock gallery = 4;
    QuoteBlock quote = 5;
    CodeBlock code = 6;
    LinkBlock link = 7;
    ListBlock list = 8;
    DividerBlock divider = 9;
    CalloutBlock callout = 10;
  }
}
```

该模型让前端保持完整样式控制，同时不依赖 HTML 或 Markdown。具体块类型与字段根据原型和真实运营内容增减。

## 9. 请求与反馈状态

### 9.1 加载状态

提交命令后：

- 历史区显示访客输入和克制的加载反馈。
- 输入框暂时禁止重复提交。
- 收到响应后，以后端消息替换加载反馈。
- 只有取得完整且可渲染的窗口数据后才切换窗口内容。
- 第一版不并发执行多条命令。

### 9.2 无效命令

后端判定无效时：

- 前端显示后端返回的完整消息。
- 不打开新窗口。
- 不拼接命令数量。
- 不在客户端进行模糊匹配或相似命令推荐。
- 保留该条历史记录。

### 9.3 有效但内容为空

命令有效但没有实际条目时，窗口仍正常打开，并使用对应模板的空状态。空状态说明由后端提供。

### 9.4 网络或 RPC 失败

- 不打开新窗口。
- 已打开的窗口保持不变。
- 命令区展示统一的网络或服务错误提示。
- 允许访客重新提交。

### 9.5 无法渲染的响应

当前端收到未支持或不完整的内容类型时：

- 窗口显示“当前内容暂时无法展示”一类降级信息。
- 记录 `request_id` 供排查。
- 不让整个页面崩溃。

## 10. 响应式与可用性原则

- 桌面端使用居中的页面内窗口。
- 移动端窗口接近全屏，避免狭小弹窗。
- 文章、代码、图片和长链接不得造成整个页面横向溢出。
- 返回和关闭操作在触摸设备上必须容易点击。
- 命令输入区不能被移动端软键盘完全遮挡。
- 正式命令由帮助内容公开，探索感主要来自输入行为、内容关联和彩蛋，而不是隐藏基本内容。

## 11. 第一版明确不做

- 多窗口并存和窗口层级管理
- 窗口拖动与缩放
- 客户端命令解析
- 复杂命令管道
- gRPC 流式调用
- 用户账号和跨设备历史
- 评论、点赞等社区功能
- 前端渲染后端任意 HTML
- Markdown 内容协议
- 前端抓取第三方网页或计算 GitHub 贡献

## 12. 可演进项

以下细节不在当前阶段一次定死，将在看到原型和真实内容后微调：

- 各模板的视觉密度和字段取舍
- 文章与长内容的结构化块类型
- 列表分页、游标或懒加载策略
- 命令历史是否本地持久化
- 浏览器前进、后退是否同步窗口状态
- 移动端窗口的具体尺寸与动画
- 哪些成功历史记录可以直接重开内容
- 特殊彩蛋是否需要独立模板

调整必须保持三个基础约束：命令逻辑属于后端，数据通过强类型 Protobuf 返回，正式内容由前端页面内窗口展示。
